# Web Development 1 Editable Course Template Design

## 1. Course Identity

**Course title:** Welcome to Web Development 1

**Audience:** Learners aged 9-14

**Duration:** Eight weeks

**Delivery:** Self-paced learning supported by one teacher-led, one-hour session each week

**Technical scope:** Strong HTML and CSS foundations, followed by one tiny optional JavaScript preview in Week 8

**Final outcome:** Every learner publishes and downloads their first small website.

### Course description

This course introduces learners to website development. Learners discover what websites are, how browsers and servers work together, and how HTML and CSS create web pages. They build one website step by step, test it, publish it through eduClub, download its files, and present it in a final showcase.

### Guided website choices

Each learner selects one safe topic:

- About Me, using non-sensitive information
- A hobby
- A favorite animal
- A school club
- A local hero

All learners follow the same coding milestones regardless of topic.

## 2. Design Principles

The course uses a project-led structure supported by a light mission adventure.

- One website grows throughout all eight weeks.
- Each week is a clearly named mission with a badge.
- The story layer motivates learners but never hides the real technical vocabulary.
- Instructions use short sentences, examples, visuals, and encouraging feedback.
- Activities support ages 9-14 through starter code, friendly hints, and optional extension challenges.
- Learners see the result of code changes immediately in the eduClub live preview.
- Knowledge is revisited in later missions so learners remember and apply it.
- Online safety, privacy, copyright awareness, and accessibility are taught as normal parts of web development.

## 3. Editable Template Model

This course is a reusable master template. System administrators and authorized teachers may adapt it for a school or class without changing the original master unless they have template-management permission.

### Editable course fields

- Course title, subtitle, description, cover image, welcome message, and estimated duration
- Age guidance, prerequisites, learning outcomes, completion rules, and certificate text
- Public showcase availability and teacher-approval requirements
- Topic choices and school-specific safeguarding guidance

### Editable module fields

- Mission title, story introduction, description, learning objectives, badge, and order
- Availability dates, mastery requirement, teacher notes, and extension guidance
- Required or optional status

### Editable activity fields

- Activity title, type, instructions, content, images, video source, links, points, and order
- Starter code, solution guidance, expected output, friendly hints, and optional challenge
- Discussion prompt, reply expectations, moderation notes, and participation rules
- Quiz questions, question types, options, correct answers, explanations, hints, and points
- Required, optional, hidden, duplicated, or deleted state

Teachers and administrators can add, edit, reorder, duplicate, hide, or remove activities. The recommended eight-mission progression remains visible as template guidance, while authorized editors may customize it for learner needs.

## 4. Learning Experience

### Standard weekly rhythm

Each one-hour teacher-led session follows this recommended pattern:

| Time | Activity |
| --- | --- |
| 5 minutes | Mission welcome and learning goal |
| 8 minutes | Child-friendly reading with an image or diagram |
| 5 minutes | Short video |
| 7 minutes | Teacher-led discussion |
| 20 minutes | Guided coding with live preview |
| 8 minutes | Interactive quiz with hints and retries |
| 5 minutes | Independent website challenge |
| 2 minutes | Reflection, progress celebration, and badge |

Self-paced learners complete the same activities in sequence. The platform saves progress and restores the latest code.

### Standard activity sequence

Every mission should contain:

1. **Mission Welcome:** A brief story moment, real learning objective, and completed-page preview.
2. **Discover:** A child-friendly reading activity supported by an image or diagram.
3. **Watch:** A short, teacher-approved video source with a written summary or transcript alternative.
4. **Talk:** A moderated discussion prompt linked to the learner's project.
5. **Try It:** A small guided example in the built-in editor.
6. **Build It:** The weekly website milestone using HTML/CSS live preview.
7. **Knowledge Check:** A mixed-format quiz with friendly hints and unlimited retries.
8. **Level Up:** An optional challenge for learners ready to go further.
9. **Reflect:** One short reflection question and a confidence check.
10. **Celebrate:** Progress feedback and the weekly badge.

Editors may adjust this sequence, but the template should include all ten activity purposes.

## 5. Eight-Week Journey

### Week 1: Mission 1 - Meet the Web

**Badge:** Web Explorer

**Essential understanding**

- A website is a collection of connected web pages.
- A browser requests and displays website files.
- A server stores or delivers those files.
- HTML gives a page structure and CSS gives it style.
- Safe websites do not reveal private learner information.

**Activities**

- Read: "What Is a Website?"
- Image: Browser-to-server request diagram
- Video: A short visual explanation of how a website reaches a screen
- Discussion: "Which website helps you learn, create, or solve a problem?"
- Quiz:
  - ABCD question identifying a browser
  - Match browser, server, HTML, and CSS to their jobs
  - Arrange request, server response, and browser display in order
  - Fill in: "A collection of connected web pages is a ____."
- Coding: Open the eduClub editor, identify the HTML and preview areas, and create a valid page skeleton.
- Build milestone: Choose a guided topic and add the page title.
- Reflection: "What do you want visitors to learn from your website?"

**Friendly hint example:** "Think about the app you use to open websites. Chrome, Edge, Firefox, and Safari are examples."

### Week 2: Mission 2 - HTML Building Blocks

**Badge:** HTML Builder

**Essential understanding**

- HTML uses elements to describe content.
- Most elements have opening and closing tags.
- Headings create a meaningful hierarchy.
- Paragraphs and lists organize ideas.
- Correct nesting keeps code understandable.

**Activities**

- Read: "HTML Is the Structure"
- Image: A labeled HTML element showing opening tag, content, and closing tag
- Video: Building a simple page with headings, paragraphs, and lists
- Discussion: "How is a web page like a book or school poster?"
- Quiz:
  - Match tags to heading, paragraph, ordered list, and list item
  - Fill in a missing closing tag
  - Choose the best heading order
  - Arrange nested list code correctly
- Coding: Practise `<h1>`, `<h2>`, `<p>`, `<ul>`, `<ol>`, and `<li>`.
- Build milestone: Add an introduction, two sections, facts, and a list.
- Level Up: Add a short quotation or fun-fact section using an appropriate HTML element.
- Reflection: "Which HTML element was most useful today?"

### Week 3: Mission 3 - Links and Images

**Badge:** Content Connector

**Essential understanding**

- Links connect pages and resources.
- Useful link text explains where a link goes.
- Images use a source and meaningful alternative text.
- Learners must use safe, permitted images and credit creators when required.
- File paths tell the browser where to find content.

**Activities**

- Read: "Connecting the Web"
- Image: Annotated link and image elements
- Video: Adding a safe image and meaningful link
- Discussion: "What makes a link helpful instead of confusing?"
- Quiz:
  - Match `href`, `src`, and `alt` to their purposes
  - Choose the best alternative text
  - Fill in a missing image attribute
  - Arrange the steps for checking whether an image may be reused
- Coding: Add links, an image, alternative text, and a link that opens the approved source.
- Build milestone: Add at least two relevant images and two useful links.
- Level Up: Turn one image into a link.
- Reflection: "How does alternative text help a visitor?"

### Week 4: Mission 4 - CSS Style Lab

**Badge:** Style Scientist

**Essential understanding**

- CSS rules contain selectors, properties, and values.
- CSS changes presentation without changing the meaning of HTML.
- Colors and fonts should remain readable.
- Consistent styles make a website easier to understand.

**Activities**

- Read: "CSS Gives a Website Its Look"
- Image: Annotated CSS rule
- Video: Styling headings, paragraphs, colors, and backgrounds
- Discussion: "How can color change the feeling of a website?"
- Quiz:
  - Match selector, property, and value
  - Fill in a missing colon or semicolon
  - Choose a readable color combination
  - Arrange a CSS rule in the correct order
- Coding: Style `body`, headings, paragraphs, links, and background colors.
- Build milestone: Create a consistent color palette and type style for the website.
- Level Up: Add hover styling to links.
- Reflection: "Which design choice best matches your topic, and why?"

### Week 5: Mission 5 - Boxes and Spacing

**Badge:** Layout Architect

**Essential understanding**

- Web content is displayed in boxes.
- Padding adds space inside a box.
- Margin adds space outside a box.
- Borders and backgrounds can group related content.
- Spacing and alignment improve readability.

**Activities**

- Read: "Every Element Has a Box"
- Image: Child-friendly box model diagram
- Video: Turning plain sections into cards
- Discussion: "Why is empty space useful in a design?"
- Quiz:
  - Match content, padding, border, and margin
  - Identify whether a spacing example needs margin or padding
  - Fill in a CSS declaration
  - Arrange box-model layers from inside to outside
- Coding: Use classes, `margin`, `padding`, `border`, `width`, and basic alignment.
- Build milestone: Organize page content into clear sections or cards.
- Level Up: Add rounded corners and a subtle shadow.
- Reflection: "What became easier to read after you changed the spacing?"

### Week 6: Mission 6 - Pages and Navigation

**Badge:** Site Navigator

**Essential understanding**

- A website may contain multiple connected pages.
- Navigation should be consistent and predictable.
- Relative paths connect files within the same website.
- Planning content before coding prevents confusion.

**Activities**

- Read: "From One Page to a Website"
- Image: A simple two-page site map
- Video: Creating and linking a second page
- Discussion: "What should a visitor be able to find quickly?"
- Quiz:
  - Match file names to page purposes
  - Choose the clearest navigation labels
  - Fill in a relative link path
  - Arrange site-planning steps in order
- Coding: Create a second HTML page and a repeated navigation menu.
- Build milestone: Connect both pages and confirm every navigation link works.
- Level Up: Add a "Back to top" link or third optional page.
- Reflection: "Could a first-time visitor move around your site without help?"

### Week 7: Mission 7 - Polish and Test

**Badge:** Bug Detective

**Essential understanding**

- Testing is part of building, not a sign of failure.
- Developers inspect one problem at a time.
- Websites should be readable on different screen sizes.
- Semantic headings, alternative text, keyboard-friendly links, and color contrast improve accessibility.
- Specific, kind feedback helps creators improve.

**Activities**

- Read: "Test, Fix, Improve"
- Image: A visual debugging checklist
- Video: Finding common HTML and CSS mistakes
- Discussion: "Describe a mistake that helped you learn something."
- Quiz:
  - Match common symptoms to possible fixes
  - Choose the most useful peer-feedback comment
  - Fill in an accessibility checklist item
  - Arrange a debugging process in order
- Coding: Use preview checks and a guided checklist to repair syntax, broken links, missing images, overflow, and readability problems.
- Build milestone: Complete peer review and improve the website.
- Level Up: Add one simple responsive CSS rule approved by the template editor.
- Reflection: "Which improvement made the biggest difference?"

### Week 8: Mission 8 - Launch Day

**Badge:** Web Creator

**Essential understanding**

- Publishing makes website files available through a web address.
- Creators should test and obtain approval before publishing.
- Website files can be downloaded and opened again.
- Presenting a project includes explaining choices and learning.
- JavaScript can add behavior, but detailed JavaScript instruction belongs in a later course.

**Activities**

- Read: "From Code to the World"
- Image: Draft, test, approve, publish, and share flow
- Video: Publishing and downloading an eduClub website
- Discussion: "What are you most proud of, and what would you build next?"
- Final knowledge check containing ABCD, matching, fill-in, and ordering questions from across the course
- Coding: Complete the final checklist and preview one tiny, optional teacher-provided JavaScript interaction.
- Build milestone: Submit for teacher approval, publish to an eduClub link, and download the HTML/CSS files.
- Showcase: Give a short presentation and one kind, useful peer-feedback comment.
- Reflection: Complete a learner self-assessment and course feedback activity.
- Celebration: Award the Web Creator badge and course certificate after completion rules are met.

The JavaScript preview is optional, supplied as a safe snippet, and explained only as a glimpse of the next course. It is not assessed as an HTML/CSS learning outcome.

## 6. Built-In Coding Experience

The eduClub coding activity should provide:

- Separate HTML and CSS editing areas
- Immediate live preview
- Starter code that editors can change
- Reset-to-starter-code with confirmation
- Automatic saving and resume support
- Clear line numbers and readable code sizing
- A simple error or checklist panel using child-friendly language
- Full-screen preview
- A milestone checklist
- Teacher view of submitted code and preview
- Website file download
- Teacher-approved publishing to an eduClub public link

The learner's website project persists across missions. A mission loads the latest saved project rather than creating an unrelated coding submission.

## 7. Quiz and Feedback Rules

### Supported template question types

- ABCD or single-choice
- Multiple-select where appropriate
- Matching
- Fill-in or short answer
- Arrange in order

### Mastery behavior

- Recommended mastery score: 80%
- Unlimited retries
- Friendly hint available after an incorrect attempt
- Explanatory feedback after submission
- Question and option order may be shuffled where doing so does not damage meaning
- The learner sees progress without shame-based language
- Editors can change mastery score, points, questions, answers, hints, and explanations

Example feedback:

- "Good try. Look at the opening tag and find the tag that should close it."
- "Almost there. Remember: padding is the space inside the border."
- "You found two correct matches. Check what a browser does with the files it receives."

## 8. Differentiation for Ages 9-14

### Support options

- Starter code and partially completed examples
- Read-aloud-friendly text and short paragraphs
- Vocabulary cards
- One hint at a time
- Visual examples of the expected result
- Teacher demonstration mode
- Reduced optional workload without removing essential outcomes

### Extension options

- Level Up activity in every mission
- Additional content section or optional third page
- More advanced selectors and responsive styling
- Independent design justification
- Peer helper role without editing another learner's work

Extensions must deepen the week's concept rather than introduce a separate technology too early.

## 9. Teacher Guidance

Each mission includes editable teacher notes covering:

- The essential concept learners must understand
- Common misconceptions
- A five-minute demonstration
- Suggested discussion follow-up questions
- Safeguarding or moderation notes
- Ways to support younger or less confident learners
- Ways to extend older or faster learners
- The expected website milestone
- A quick end-of-session progress check

Discussion replies are moderated according to school policy. Teachers can edit prompts, close a discussion, hide inappropriate replies, and provide a model response.

## 10. Assessment and Completion

Assessment combines:

- Quiz mastery
- Completion of weekly coding milestones
- Final website functionality and presentation
- Reflection activities
- Accessibility and safety checks
- Showcase participation and useful peer feedback

### Completion requirements

A learner completes Web Development 1 by:

- Finishing all eight missions
- Reaching at least 80% on required quizzes
- Completing every required website milestone
- Testing links, images, readability, and core accessibility checks
- Receiving teacher approval for the final website
- Publishing the website when public publishing is enabled
- Downloading the HTML/CSS website files
- Presenting the website during the Week 8 showcase
- Giving one kind, useful peer-feedback comment
- Completing the final reflection

If a school disables public publishing, teacher-approved private showcase completion satisfies the publishing requirement. The downloadable files remain available.

## 11. Publishing, Safety, and Showcase

- Publishing requires teacher approval by default.
- Schools may disable public links.
- Public links use a platform-controlled address and do not expose learner contact details.
- Learners are instructed not to publish addresses, phone numbers, private schedules, passwords, or other sensitive details.
- "About Me" projects use safe, non-sensitive information.
- Image activities teach permissions, credits, and alternative text.
- Teachers can unpublish a project.
- Downloaded packages contain the learner's website files and required approved assets.
- Showcase feedback follows a simple pattern: one strength and one kind suggestion.

## 12. Certificate and Recognition

After meeting all completion requirements, the learner receives:

- Final **Web Creator** badge
- **Web Development 1: Web Creator** certificate
- A completion record linked to the course allocation

Weekly badges are:

1. Web Explorer
2. HTML Builder
3. Content Connector
4. Style Scientist
5. Layout Architect
6. Site Navigator
7. Bug Detective
8. Web Creator

Badge names, images, and certificate wording are editable template fields.

## 13. Template Success Criteria

The course template is successful when:

- A learner can explain, in age-appropriate language, what a website, browser, server, HTML, and CSS do.
- A learner can create and connect structured HTML pages.
- A learner can style readable pages using foundational CSS.
- A learner can add safe images, useful links, navigation, and alternative text.
- A learner can use a basic testing process to find and repair mistakes.
- Every completing learner has a teacher-approved website, a public or private showcase outcome, and downloadable files.
- Teachers can customize all lesson-level content without rebuilding the course structure.
- The experience remains clear and usable for both a supported nine-year-old and an independent fourteen-year-old.

## 14. Out of Scope

Web Development 1 does not teach:

- JavaScript syntax or programming fundamentals beyond the optional Week 8 preview
- Backend development, databases, authentication, or APIs
- Advanced CSS frameworks or build tools
- Commercial deployment, custom domains, or paid hosting
- Unmoderated public communication

These topics belong in later courses.
